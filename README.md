# أكاديمية الهندسة الميكانيكية وهندسة الأنابيب

منصة تدريب أونلاين كاملة (Landing Page + Dashboard) مبنية بـ Next.js (React + TypeScript) و
Prisma و SQLite/PostgreSQL و NextAuth (Auth.js). تدعم ثلاثة أدوار: **مدير (Admin)**،
**مدرب (Trainer)**، و **متدرب (Student)**، مع رفع كتب PDF وفيديوهات وسلايدز لكل دورة.

## المكدس التقني (Tech Stack)

- **Frontend/Backend**: Next.js 16 (App Router, Server Actions) + React 19 + TypeScript
- **قاعدة البيانات**: Prisma ORM — SQLite في التطوير، ويمكن التبديل لـ PostgreSQL في الإنتاج بسطر واحد
- **المصادقة**: NextAuth (Auth.js) v5 — تسجيل دخول بالبريد وكلمة المرور، صلاحيات حسب الدور
- **التنسيق**: Tailwind CSS v4 (تصميم RTL بالعربية، ثيم غامق بلون كحلي وذهبي)
- **تخزين الملفات**: نظام ملفات محلي (قابل للترقية لـ S3 أو Supabase Storage لاحقًا)

## التشغيل محليًا

```bash
npm install
cp .env.example .env
# عدّل .env: ضع مسارًا مطلقًا (absolute path) لـ DATABASE_URL يشير إلى prisma/dev.db
# داخل مجلد المشروع لديك، وغيّر AUTH_SECRET بقيمة عشوائية جديدة (openssl rand -base64 32)
npx prisma migrate dev    # ينشئ قاعدة بيانات SQLite ويطبّق المخطط
npm run db:seed           # يضيف حساب المدير والدورات الأربعة وحساب متدرب تجريبي
npm run dev               # يشغّل الموقع على http://localhost:3000
```

> **ملاحظة مهمة**: استخدم مسارًا **مطلقًا** لملف SQLite في `DATABASE_URL` (مثل
> `file:/home/you/project/prisma/dev.db`) وليس مسارًا نسبيًا مثل `file:./dev.db` — لأن أداة
> Prisma (migrate/seed) وتطبيق Next.js وقت التشغيل يفسّران المسار النسبي بشكل مختلف، فينتهي بك
> الأمر بملفي قاعدة بيانات مختلفين دون أن تشعر. إعداد Docker المرفق يستخدم مسارًا مطلقًا بالفعل
> فلا داعي للقلق عند النشر به.

### حسابات ابتدائية بعد التشغيل (Seed)

| الدور | البريد الإلكتروني | كلمة المرور |
|---|---|---|
| مدير (Admin) | `albarasi37@gmail.com` | `MR_2026` |
| متدرب تجريبي | `student@example.com` | `Student123!` |

**غيّر كلمة مرور المدير فورًا بعد أول تسجيل دخول** (لا توجد صفحة لتغيير كلمة المرور بعد — يمكن
تحديثها مباشرة من قاعدة البيانات أو بإعادة تشغيل seed بكلمة مرور جديدة).

## الأدوار والصلاحيات

- **مدير (ADMIN)**: يدير كل الدورات، يضيف مدربين ومتدربين، ينشر/يخفي الدورات، يسجّل متدربين في
  أي دورة، ويرى كل الإحصائيات من `/dashboard/admin`.
- **مدرب (TRAINER)**: يدير دوراته الخاصة فقط (إنشاء دورة، إضافة وحدات، رفع كتب/فيديوهات/سلايدز،
  تسجيل متدربين في دوراته، تعديل ملفه الشخصي) من `/dashboard/trainer`.
- **متدرب (STUDENT)**: يسجّل حسابه من `/register`، يلتحق بالدورات المجانية/المنشورة تلقائيًا، ويشاهد
  محتوى دوراته المسجَّل بها فقط من `/dashboard/student`. أي ملف مرفوع يُخدَّم عبر مسار محمي
  (`/api/files/[id]`) يتحقق أن المستخدم مدير، أو مالك الدورة، أو مسجَّل فيها — قبل السماح بالوصول.

## إضافة الدورات الأربع لاحقًا

الدورة الأولى (**الكورس الشامل في الأنابيب والهندسة الميكانيكية**) منشورة ومهيّأة بـ 10 وحدات (كتاب
لكل وحدة). الدورات الثلاث الأخرى (**التكييف المركزي**، **SolidWorks للأنابيب**، **أيزومترك
بالأوتوكاد**) موجودة كمسودات جاهزة بوحداتها الأساسية — كل ما تحتاجه هو تسجيل الدخول كمدير، فتح
كل دورة من `/dashboard/admin/courses`، ثم:

1. رفع صورة الغلاف (Poster) ورابط الفيديو التقديمي من نموذج "تعديل بيانات الدورة".
2. رفع الكتب (PDF) والفيديوهات والسلايدز داخل كل وحدة من نموذج "رفع الملف".
3. الضغط على زر "مسودة" لتغييره إلى "منشورة" حتى تظهر للمتدربين.

## النشر (Deployment): سيرفر + دومين + قاعدة بيانات حقيقية

هذا المشروع تطبيق Next.js كامل (فرونت + باك إند + قاعدة بيانات) يحتاج **سيرفر Node.js يعمل
باستمرار** (وليس مجرد صفحات ثابتة) لأن رفع الملفات يُخزَّن على قرص السيرفر. أسهل طريقة:

### الخيار المُوصى به: VPS + Docker + دومين

1. **استأجر VPS** (مثل Hetzner، DigitalOcean، أو أي مزوّد) بنظام Ubuntu، وثبّت Docker.
2. **اربط الدومين**: من لوحة تحكم الدومين، أضف سجل `A` يشير إلى IP السيرفر.
3. **جهّز ملف البيئة** للإنتاج:
   ```bash
   cp .env.example .env.production
   # عدّل AUTH_SECRET بقيمة عشوائية جديدة، وأضف:
   # AUTH_URL=https://your-domain.com
   ```
4. **شغّل التطبيق**:
   ```bash
   docker compose up -d --build
   docker compose exec app npm run db:seed   # مرة واحدة فقط، أول تشغيل
   ```
   التطبيق يعمل الآن على المنفذ `3000` داخل السيرفر.
5. **اربط الدومين بـ HTTPS** بوضع reverse proxy أمام التطبيق (يمنحك شهادة SSL مجانية تلقائيًا)،
   مثل [Caddy](https://caddyserver.com) بملف `Caddyfile` بسيط:
   ```
   your-domain.com {
     reverse_proxy localhost:3000
   }
   ```
   أو Nginx + Certbot بالطريقة التقليدية.

بهذا تحصل على رابط مثل `https://your-domain.com` يمكنك مشاركته مع الطلاب مباشرة.

### التخزين والبيانات في الإنتاج

- قاعدة البيانات الافتراضية SQLite (ملف واحد) — مناسبة لعدد متدربين متوسط. للتوسّع لاحقًا:
  1. أنشئ قاعدة PostgreSQL (مثل [Neon](https://neon.tech) أو [Supabase](https://supabase.com) مجانًا).
  2. غيّر `provider = "sqlite"` إلى `provider = "postgresql"` في `prisma/schema.prisma`.
  3. عدّل `DATABASE_URL` في `.env.production` برابط PostgreSQL.
  4. شغّل `npx prisma migrate deploy`.
- الملفات المرفوعة (كتب/فيديوهات) تُخزَّن في `storage/uploads` على قرص السيرفر — تأكد من عمل
  **نسخ احتياطي دوري** لهذا المجلد وملف قاعدة البيانات. عند النشر بـ Docker Compose المرفق، كلاهما
  محفوظ في Docker volumes تلقائيًا.
- بديل بلا خادم (Vercel وغيره): يتطلب تحويل التخزين المحلي إلى تخزين سحابي (S3 أو Supabase Storage)
  لأن هذه المنصات لا توفر قرص تخزين دائم — هذا تغيير برمجي لم يُنفَّذ في هذه النسخة.

## الأمان

- كل عمليات الرفع تُفحص بامتداد الملف ونوعه وحجمه الأقصى (`src/lib/storage.ts`).
- كل الملفات تُخدَّم عبر مسار محمي بجلسة تسجيل الدخول والصلاحية، وليست عامة تحت `/public`.
- كلمات المرور مشفّرة بـ bcrypt، والجلسات موقّعة بـ `AUTH_SECRET` — لا تشارك هذه القيمة أو ترفعها لأي مكان علني.
- غيّر `AUTH_SECRET` وكلمة مرور حساب المدير الافتراضية فورًا في أي بيئة إنتاج حقيقية.
